# Re.KrtC 本机运行性能

本文引用的原始结果、生成源码副本、汇编、IR 快照和日志均在本地归档，不随 PR 提交。 测量数值与构建哈希属于文中记录的历史版本，不代表后续规范整改后的新测量。

2026-09-12，AMD Ryzen 9 8945HX，Linux x86-64，NVMe / ext4。使用当前 `Re.KrtC/build/KrtC` 生成本机可执行文件；编译器 SHA-256 和完整数据见 `RuntimeResults.json`。

本页已更新为普通整数指令精简后的结果；此前的 159.66 ms / 1733.37 ms 等原始数据保存在 修复前记录（`BeforeScalarFixRuntimeResults.json`）。同环境交替对照见 [Fibonacci 性能退化定位与修复](FibComparisonReadMe.md)。

每项独立启动 10 次，串行执行，取**算术平均值**。没有预热轮次，也没有剔除样本。程序内部使用 `CLOCK_MONOTONIC` 计时；下表“测试耗时”不包含编译、进程启动、辅助缓冲区初始化、计时后的结果校验和进程退出清理。另记录从启动子进程到退出的墙钟时间。

## 测试内容与校验

- [空循环](Runtime/test_empty_loop.krt)：`for (; i < 100000; i++) { }`，使用 `int32` 计数器；核对最终值为 100000，并从反汇编确认保留了向后的循环跳转。
- [fib35](Runtime/test_fib35.krt) / [fib40](Runtime/test_fib40.krt)：朴素双分支递归，`n <= 1` 时返回 `n`，没有记忆化。核对结果分别为 9,227,465 和 102,334,155，并确认生成了递归调用指令。
- [输出](Runtime/test_output.krt)：循环体只有 `Console.Write(i++)`，从 0 输出到 99999，不带文字、空格或换行。标准输出写入普通文件，逐字节核对全部 488,890 字节。耗时包含整数转字符串和每次输出调用，不包含终端绘制，也没有对输出文件调用 `fsync`。进程退出释放资源的时间仅计入墙钟时间列。
- [文件 I/O](Runtime/test_file_io.krt)：使用一个临时文件，10 万次写入和 10 万次读取，每次 4096 字节，总计写 390.625 MiB、读 390.625 MiB。计时包含打开文件、写入、一次 `fsync`、定位到文件头、`POSIX_FADV_DONTNEED`、读取、额外一次 EOF 检查和关闭文件。循环内检查系统调用返回值及读取块的首尾字节，结束后核对文件大小与首尾完整数据块。临时文件位于项目所在 NVMe / ext4，测试完成后自动清理。

`POSIX_FADV_DONTNEED` 在写入同步后请求丢弃该文件的页缓存；这是内核建议接口，不能把结果当作完全绕过缓存的裸盘性能。输出数据和 I/O 缓冲区均实际写入、读取，没有重定向到 `/dev/null`。

## 复现

先在 `Re.KrtC` 目录构建当前编译器，然后在项目根目录运行：

```sh
python3 Test/Performance/RuntimeBenchmarks.py --rounds 10
```

脚本将生成 `RuntimeResults.json`。可用 `--only fib35 fib40` 选择用例，用 `--output /tmp/RuntimeResults.json` 指定结果文件。编译、输出和 I/O 中间文件均放在临时目录；库源码复制到临时目录后再编译。
