本文引用的原始结果、生成源码副本、汇编、IR 快照和日志均在本地归档，不随 PR 提交。 测量数值与构建哈希属于文中记录的历史版本，不代表后续规范整改后的新测量。

编译速度确实曾退化；本轮修复了后端按函数清空整张临时槽表的开销。最终默认级别对比中，200 个普通函数从 17.43 ms 降至 10.57 ms，1000 个普通函数从 141.01 ms 降至 105.95 ms，500 个递归函数从 195.85 ms 降至 178.79 ms。空文件和小 Fib 文件基本不变。

2026-09-13，AMD Ryzen 9 8945HX，固定逻辑 CPU 0；每项先做一次不计时预热，再启动十次独立编译器进程、交替版本顺序。均值包含进程启动、编译、链接及写文件；使用温热的文件系统缓存。可执行产物在计时外检查结果，IR 对照只生成文本。所有样本、子进程 CPU 时间和源文件哈希均保留；计时期间没有并行构建或测试。

最初的退化调查比较 `1a04b02c…` 与 `baed7a2e…`：200 个普通函数慢 8.81%，1000 个慢 4.33%，500 个递归函数慢 13.88%，对应 IR 对照变化小于 1%。后端每个函数清零 4096 个临时槽和 1024 个局部槽，新增尾递归元数据后放大了清零成本。现在只在实际分配槽时初始化，保留跨函数状态隔离。新 IR 内联也为大调用方限制增长；函数调用名称改由 IR arena 管理，回收时的分配平衡有 C 回归断言。

复现命令：

```bash
python3 Test/Performance/CompileSpeed/Run.py --before Re.KrtC/build/BeforeO3/KrtC --output /tmp/CompileDefault.json
python3 Test/Performance/CompileSpeed/Run.py --before Re.KrtC/build/KrtC --after-flag=-O3 --output /tmp/CompileO3.json
```

`Run.py` 在本地生成 `Sources/`，其中 `Sources/libs/` 从项目库复制输入；编译生成物在忽略的 `Work/` 目录，不复用历史 `.kro` 产物。旧测量脚本与输入 `InitialTiming/`、最终输入副本 `FinalSources/` 均仅在本地归档，两个结果文件各自记录完整源码 SHA-256。复现原始对照需要相应历史编译器和输入；使用新源码或新库生成的结果应单独记录。最终每个结果文件包含 13 项 × 2 个版本 × 10 次，共 260 次有效编译；两个版本的全部可执行用例均验证通过。
