# 66–126 位整数精度

SelfHost 的 `int66` / `uint66` 到 `int126` / `uint126` 均使用 16 字节物理存储。运算仍按声明位宽截断，无符号结果清除高位，有符号结果从实际符号位扩展到 128 位。`int128` / `uint128` 保留原有行为。

转换、类型化读取、参数、返回值和写入均归一化。二元运算采用较大精度操作数的符号域；相同精度中有无符号操作数时采用无符号域。移位保留左操作数类型。自增、自减保存一次求出的地址和旧值，归一化后写回，再按前缀或后缀形式返回新值或旧值。

这些操作由现有 `WideLiteral` / `WideBinary` IR 表达；KRO、ASM 和 VM 共用这一精度语义，无需新的字节码指令。

## 实际差分结果

2026-10-01，最初的 Re.KrtC 和 SelfHost 快照执行边界程序得到以下差分；后续浮点修复见下一节：

| 案例 | Re.KrtC | SelfHost 修复前 | SelfHost 修复后 |
| --- | --- | --- | --- |
| uint66 / int66 / uint126 显式整数截断 | 正确 | 未按声明精度截断 | 正确 |
| int66 溢出、uint66 前缀/后缀自增 | 正确 | 错误 | 正确 |
| int126 数组元素经 ref 更新 | 正确 | 错误 | 正确 |
| 通过 int128 指针修改物理存储后，按 int66 读取 | 正确 | 高位泄漏 | 正确 |
| uint66 按位取反及负号 | 正确 | 错误 | 正确 |
| 负 int66 与 uint64 运算及比较 | 正确 | 符号域不完整 | 正确 |
| float64 → 自定义宽整数的边界转换 | 编译成功，执行结果错误 | 未归一化 | 正确 |
| 类字段自增及字段 ref | 诊断拒绝 | 可接受，但精度错误 | 正确执行 |

早期 Re.KrtC 的浮点边界反例为 `(uint66)73786976294838206464.0` 应得到零，以及 `(int66)36893488147419103232.0` 应得到负的 int66 最小值。后续修复了种子的双 limb 浮点转换，当前种子和原生编译器均通过这两个数学截断案例。

## 浮点舍入

宽整数转 float32/float64 直接提取整数 mantissa、guard 和 sticky 位，按最近偶数舍入一次并组装 IEEE 位模式。float32 不经 float64 中间值；VM 采用同样的目标精度。零、有符号最小值、进位及 float32 溢出分别处理。

例如 `2^117 + 2^64 + 1` 转 float64 应得到 `2^117 + 2^65`；分别转换高/低 limb 后相加会错误地舍入到 `2^117`。`2^100 + 2^76 + 1` 转 float32 也不能先转 float64 再缩窄。

## 验证

`Test/SelfHost/test_wide_precision.py` 实际执行全部 31 种偶数位宽的算术、溢出、移位和转换。66 / 94 / 126 位程序还分别通过 Re.KrtC 与 SelfHost 的 O0 / O2 / O3 编译并执行；另覆盖调用、返回、ref、数组、类字段、指针、地址求值次数、前缀/后缀、浮点转换及 VM。

浮点回归另使用纯整数参考算法计算 36 个预期位模式，覆盖半 ULP、最近偶数、sticky 位、负数、int128 最小值及 uint128 最大值，在种子/原生 O0/O2/O3 与 VM 中执行。

```sh
SELFHOST_COMPILER=/absolute/path/to/native/compiler python3 -m unittest Test.SelfHost.test_wide_precision
```
