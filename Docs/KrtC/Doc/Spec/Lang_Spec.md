# Re.KrtC 语言实现说明

本文描述仓库 C 版编译器 `Re.KrtC` 当前实现的核心语言路径，不是对未来语言设计的承诺，也不代表 SelfHost 已达到相同能力。需要确认特定语法时，应以 `Re.KrtC/src/Compiler/Frontend/` 中可达的解析和语义路径及原生执行结果为准。

## 程序入口和声明

普通可执行程序使用返回整数状态码的入口：

```krt
int32 main() {
    return 0;
}
```

源码可包含函数、变量、控制流和类型声明。解析器、语义分析器和后端共同决定某项声明是否可用；Token 表中出现某个关键字不等于其完整语义已实现。

## 值类型

编译器支持常用有符号/无符号整数、浮点数、`bool`、`char`、`string` 和 `void`。整数类型包含 `intN`、`uintN`，其中偶数位宽 `N` 从 2 到 128；实际存储按可容纳该位宽的字节数取 1、2、4、8 或 16 字节。位宽、转换和运算规则以 `Tokenizer.c`、整数 IR 与 KRO 后端实现为准。

示例：

```krt
int32 main() {
    int6 small = 31;
    small++;
    return small == -32 ? 0 : 1;
}
```

## 托管数组

托管数组可通过 `new T[count]` 或数组字面量创建：

```krt
int32[] values = new int32[3];
values[0] = 10;
int32[] copy = [10, 20, 30];
```

编译器可确定长度的托管数组及内联定长数组访问要求整数索引。读、写和取元素地址前会检查索引下界与上界；越界时程序以状态码 `70` 终止。数组表达式与索引表达式只求值一次，赋值的边界检查先于右侧表达式求值。托管堆数组使用后通过 `delete` 释放。

这些保证针对编译器能够识别的托管数组。字符串和裸指针的索引不使用托管数组长度元数据；不要把裸指针访问当作有边界保护。

## 指针与底层内存

指针类型和指针算术受语义检查约束；底层访问使用 `unsafe(using krt.mem;)`。`stackalloc T[count]` 创建当前函数栈帧中的缓冲区。裸指针没有关联长度，索引越界由程序负责避免。对调用方传入的地址、别名和指针生命周期，编译器不提供通用内存安全保证。

## 字符串与库

字符串在当前运行时和 `libs/System/String.krt` 中按零结尾字节序列处理；库的长度和索引语义以字节计，不等同于 Unicode 字素或码点计数。字符串及数组的分配、复制和释放规则见[内存模型](Memory_Model.md)与[API 概览](../Api/Api_Reference.md)。

## 类、结构体和控制流

解析器和语义实现包含类、结构体、函数、条件、循环、异常和其他语言构造。不同构造的限制并不完全相同；新增或改动语法时，应检查解析、绑定、IR 和原生后端，不应从其他编译器的支持范围推断 Re.KrtC 的行为。

## 运行目标

本文示例使用 CMake 构建的 `KrtC` 生成原生可执行文件，并由 ArkLink 完成链接。构建命令见[用户手册](../Guide/User_Manual.md)。
